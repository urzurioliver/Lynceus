# Lynceus
Proyecto de detección de personas mediante ondas wifi.
# IDEA GANERAL 
La idea sería usar un router de wifi Tp-link modelo: TD-W8960N y un ESP32 S3 para que este capte el CSI de las ondas del router. El CSI es el Channel State Information, y da información sobre las ondas físicas del wifi, como su amplitud y su fase. Estas magnitudes varían dependiendo del trayecto que toman, con lo cual si algo cambia en el ambiente también van a cambiar la amplitud y la fase. Nos aseguramos de que haya tráfico todo el tiempo haciendo un ping constante con el router. La idea sería que el ESP capte ese CSI y le mande a un puerto de una computadora (que tiene una ip fija) ese mismo CSI, para que se procesen estos datos. Aca va a ser importante filtrar grandes movimientos, (como los de un ventilador) y sólo prestar atención a movimientos muy ligeros como los del pecho de una persona cuando respira. Así, vamos a poder determinar si una persona está en una habitación, y también ver su respiración y su ritmo cardiaco, además de mapearla (idealmente). Además, todos estos datos van a estar visibles en una linda interfaz :).

Por la parte de hardware, compramos un ESP32 S3 (por nuestra cuenta) y nos encargamos de cargarle el código necesario del repositorio “RuView” para captar el CSI y mandárselo a la computadora. Tuvimos que aprender a usar ESP-IDF una extensión de Visual Studio Code, porque el código fue hecho con esta extensión, especial para ESP32 's. Una vez hecho configuramos lo necesario para adaptarlo a nuestro router (nombre de la red, contraseña, ip de la computadora, etc). Conseguimos nuestro router, y le configuramos el ancho de banda y el canal. Además, quisimos intentar el lograr que se pueda mapear a la persona en el ambiente, para no solo saber si hay una persona presente, sino también averiguar dónde está exactamente. Con esto tuvimos un par de complicaciones. Para hacer que esto funcione (medianamente) necesitabamos tener mas de un nodo recibiendo el CSI, es decir, por lo menos 3 esp32 para poder sacar una distancia con trigonometría, viendo la diferencia de tiempo entre lo que tardaban en llegar las subportadoras al ESP32, pero surgio un problema: los relojes internos de los esp32 tenían que estar muy sincronizados, y en la realidad no pasa. Por eso descartamos la idea de mapeo con ESP. Así pasamos a comprar el módulo HLK-LD2410C, que sirve para detectar personas y te devuelve coordenadas en X e Y sobre dónde está. Para aumentar su rango de detección lo pusimos arriba de un servomotor para que vaya girando en un rango de 150 grados. 
Por ahora el servo y el módulo están controlados por un arduino, más tarde veremos si lo integramos todo al esp32 o si dejamos el arduino. 
Por el momento tenemos al ESP32 captando el CSI del router y se lo manda exitosamente a la computadora. Estamos viendo cómo programar el módulo HLK-LD2410C para obtener datos de las coordenadas, y también queremos obtener una prueba de funcionamiento lo más fiable posible (hasta ahora no fueron muy exitosas…), para lo cual vamos a hacer una caja de Faraday pequeña con aluminio.

A nivel programación, estamos trabajando con una base de datos no relacional con MongoDB, en la que almacenaremos las distintas sesiones, información como csi o rpms de cada uso. A su vez, tenemos una API con algunos endpoints hecha en python con fastAPI ya que también tendremos una interfaz que muestre los rpm si es que detectamos presencia, y la distancia a la que se encuentra la persona.

Para trabajar el CSI y datos de la onda, estamos encontrando dificultades, ya que, si bien pudimos hacer la lectura del puerto 5005 sin mayor complejidad, a la hora de probar el código que determina la presencia humana, inicialmente vimos que siempre nos daba presencia, y ahora, con cambios que implementamos, deja de darla. Para esto, estamos contemplando 2 soluciones. Por un lado, nos dimos cuenta que no tiene sentido comparar el dato recibido solo con el filtro estándar que definimos nosotros, sino que también deberíamos ver cómo contrasta con los paquetes anteriores de la misma sesión. Por otro lado, también estamos contemplando e investigando maneras de resolver este problema al utilizar una librería, ya que procesar la onda es algo no trivial, y así podríamos pasar a enfocarnos en otras partes del desarrollo del proyecto, asegurando más precisión y eficiencia en los resultados.
